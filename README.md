# دليـل النـشـر والـتـرجـمـة والـتـشـغـيـل الـنـهـائـي لمنظومة آدم الأردنية 🇯🇴
## (Production Release & Deployment Architecture)

يرشدك هذا الدليل التفصيلي إلى كيفية إدارة الملفات، وحماية مفاتيح API، وبناء الحزم ونشر التطبيقات على المتاجر الرسمية لضمان تشغيل آمن ومقبول بالكامل على متجري Google Play و Apple App Store.

---

## 1. بنية كود المشروع والملفات المرفقة (Source Code)
المشروع الحالي هو نظام **كامل ومتكامل (Full-Stack Web & Hybrid Core)** مبني باستخدام:
* **الفروتنيد (Client-Side):** React 19 + TypeScript + Vite + Tailwind CSS.
* **الباكينيد (Server-Side):** Node.js Express Server لتأمين البيانات وحظر التواصل المباشر مع قواعد البيانات من الأجهزة المحمولة.
* **محاكي التنزيل المدمج:** يحتوي الكود على واجهات التثبيت الذاتي لتنزيل الحزم التجريبية.

عند الضغط لتصدير الكود المصدري كملف مضغوط (ZIP) من القائمة، سيحتوي الملف على:
1. **الكود المصدري بالكامل** (`src/`, `server.ts`, `vite.config.ts`, `package.json`).
2. **ملفات الإعدادات والتهيئات البيئية** للعمل والإنتاج المباشر.
3. دليلاً شاملاً للنشر الفوري.

## 2. الأمن السيبراني: إخفاء حماية مفاتيح التشفير والـ (API Keys) 🔒
لحماية تطبيقك من الاختراق أو فك الضغط (Reverse Engineering):
* **حظر إدخال مفاتيح الكود الصلبة (Hardcoded Keys):** لا تضع أي رمز سري أو سلسلة اتصال قاعدة بيانات (`Connection Strings`) أو مفتاح Gemini API داخل الجزء العميل (`src/`).
* **استخدام الخادم كوسيط آمن (Secure Proxy):** كافة الطلبات التي تحتاج مفاتيح تواصل (مثل خدمة الخرائط، إرسال الإشعارات، والذكاء الاصطناعي AI) ترسل عبر طبقة الباكيند متمثلة بـ `server.ts`.
* **ملف البيئة الآمنة (`.env`):**
  يتم قراءة المتغيرات والمفاتيح بالخادم عن طريق بيئة التشغيل فقط:
  ```env
  # .env - يتم الاحتفاظ به في خادم الاستضافة الآمن ولا يضمن نهائياً داخل حزمة الأندرويد أو الآيفون
  GEMINI_API_KEY=your_secured_gemini_key_here
  DATABASE_URL=your_secured_database_connection_url_here
  PORT=3000
  ```
  تأكد من إدراج `.env` داخل ملف `.gitignore` لمنع رفعه للمستودعات البرمجية العامة.

## 3. تحويل الكود المصدري إلى تطبيقات هواتف ذكية (iOS & Android) 📱
بما أن المشروع مبني بتقنيات الويب الحديثة فائقة السرعة، يتم تغليفه باستخدام **Capacitor** أو **Cordova** للحصول على حزم هجينة أصلية فائقة الاستقرار:

### أ) تهيئة البيئة وتثبيت المقابس اللاسلكية:
```bash
# 1. بناء ملفات الإنتاج المجمعة للويب أولاً
npm run build

# 2. تثبيت كاباسيتور في مجلد المشروع
npm install @capacitor/core @capacitor/cli

# 3. تفعيل وإعداد معايير المنصة
npx cap init "Adam Ride-Share" "com.adam.rideshare" --web-dir=dist

# 4. إضافة منصة الأندرويد والآيفون
npm install @capacitor/android @capacitor/ios
npx cap add android
npx cap add ios
```

## 4. شروط وإجراءات النشر على متجري التطبيقات (AAB for Google / IPA for Apple) 🛒

### أولاً: متجر الأندرويد (Google Play Console)
أعلنت جوجل مؤخراً حظر رفع حزم الـ `*.apk` للنشر النهائي، والبدء بقبول المطورين حصراً لحزم حزم تطبيقات الأندرويد الذكية **Android App Bundle (`.aab`)**:
1. افتح المشروع المولد داخل **Android Studio** عبر الأمر:
   ```bash
   npx cap open android
   ```
2. اذهب إلى القائمة العلوية واختر: **Build -> Generate Signed Bundle / APK**.
3. حدد الخيار الجديد **Android App Bundle (.aab)**.
4. قم بإنشاء أو إدراج مفتاح التوقيع الرقمي الآمن الخاص بك (`KeyStore`).
5. يتم حفظ الملف الناتج بصيغة `.aab` في مجلد `release` لرفعه مباشرة للمتجر.

### ثانياً: متجر الآيفون (Apple App Store)
تفرض آبل بناء حزمة التطبيق الرسمية الحصرية بصيغة **IPA (`.ipa`)** وتوقيعها من خلال أجهزة MacOS حصرية:
1. افتح مشروع الآيفون المولد داخل تطبيق Xcode عبر الأمر:
   ```bash
   npx cap open ios
   ```
2. حدد الجهاز المستهدف للتشغيل كـ **Any iOS Device (arm64)**.
3. من القائمة العلوية لـ Xcode اختر: **Product -> Archive**.
4. بعد اكتمال الأرشفة بنجاح، ستفتح شاشة منظم الأرشيف (`Organizer`).
5. اضغط على زر **Distribute App** وحدد خيار النشر عبر متجر آبل (**App Store Connect**).
6. سيقوم الأداة أوتوماتيكياً بتحزيم الملف وتوقيعه ثم رفعه وتوفير حزمة الـ `.ipa` من المتاجر الرسمية.

## 5. ربط التطبيقات الموزعة بلوحة التحكم ونظام الـ (API Endpoints) 🔗
لكي تتصل حزمة الهاتف المثبتة لدى الراكب أو الكابتن بالباكيند المركزي، يتم تحديث مسار الاتصال الأساسي في ملف تهيئة الاتصال بالفروتنيد:

* **الاتصال المحلي للتجريب والتطوير:** `http://localhost:3000/api`
* **الاتصال المباشر بنسخة الإنتاج الحية (Cloud Storage / Cloud Run):**
  يجب تغيير مسار الـ Base URL المبرمج ليتصل بالسيرفر المرفوع على سبيل المثال:
  ```typescript
  // src/config.ts
  export const API_BASE_URL = "https://your-production-server-domain.com/api";
  ```

### نقاط النهاية الأساسية المدعومة (Core API Endpoints):
* **تنسيق الرحلات التجميعية اليدوي والجغرافي:** `/api/rides`
* **إدارة طلبات الركاب الفردية والرادار الفرعي:** `/api/requests`
* **المسؤول وإجراءات التحديث:** `/api/admin`
* **المحادثة الفورية للكباتن والركاب:** `/api/messages`

## 6. قاعدة تصفية شاشات وتطبيقات المتاجر (تنبيه هام) ⚠️
> **"لا ترفع لوحة تحكم الإدارة أو الداشبورد لمتاجر الهواتف المحمولة"**

عند تفريغ وبناء التطبيقات للمتاجر، يرجى الالتزام الصارم بالتالي:
1. **تطبيق الراكب (Passenger App):** يُبنى كحزمة مستقلة تماماً موجهة لعموم الركاب، ولا يحتوي على أي روابط أو أزرار تؤدي للداشبورد الإداري.
2. **تطبيق الكابتن (Driver App):** يُبنى كحزمة مستقلة ثانية موجهة للفئة المستهدفة من سائقي التكسي والكباتن، مع تأكيد رفع ملفات الهويات والورقيات للمراجعة.
3. **لوحة CRM والداشبورد الداخلي:** يتم إدارتها واستضافتها كلوحة تحكم سحابية ويب آمنة موجهة لمدراء وعمليات منظومة آدم ومحظورة عن الجمهور بكلمات سر قوية. يرجى تجنب توفيرها كتطبيق هاتف عام تماماً للمحافظة على أمان وموثوقية المنظومة.
